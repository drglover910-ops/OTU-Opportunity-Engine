# v0.13.0 — familiar layout, uploads and résumé design

Navigation follows the owner's reference: New chat, Opportunities, Library, Connections and Explore; Help and Settings/tools sit below recents. Recents display conversation names, with rename in the menu. Ready-to-review remains available through Settings/tools and a prominent opportunity-chat shortcut. Navigation/chat typography and spacing are larger; secondary conversation controls remain collapsed. Matrix animation and motion controls are preserved.

The composer + button uses the native file picker. iPad Files can expose iCloud Drive and installed/configured providers such as Google Drive. This does not add an in-app Drive OAuth integration. Private photo previews decode and resize raster images to JPEG, enforce size/dimension bounds and exclude active SVG/HTML. Other files use intentional streamed downloads. Uploaded text, documents and images are not automatically supplied to inference, extracted, OCR'd or treated as career facts.

A separate private attachment store under OTU_DATA_DIR accepts 4 MiB chunks, with up to 1 GiB (1,073,741,824 bytes) per file. Each upload reserves its full size against a default 5 GiB application allowance. This is not an assertion of the user's Hugging Face account capacity. OTU_ATTACHMENT_QUOTA_BYTES can change the app allowance after actual bucket capacity is checked. Start/list metadata are scoped to the selected conversation. Upload IDs are random server-generated keys, not user paths. Sequential offsets and byte-identical retries are validated. Selecting the same file again resumes its saved offset; partial uploads expire after seven days. Progress, partial cancellation, explicit-confirmation completed-file removal and a usage meter are included. Opportunity workspace moves retain attachment scope.

Metadata and file data persist in the existing mounted storage. The original bounded backup ZIP feature does not include this separate attachment store; the UI says so. Save originals individually when an independent backup is needed. No completed files, career master sources or prior documents are automatically deleted.

The new PDF résumé uses selectable text, a navy/gold name banner and border, contact strip, two-column skills and experience area, sidebar cards and source-based projects/education. Word exports use a matching editable two-column layout; exact Word pagination depends on the viewer. Layout adapts to actual verified text; it is not a flattened copy of the sample image. Sample-image Ottawa contact details, dates, education and availability are not facts. No project thumbnail, platform logo, availability or unverifiable credentials are fabricated. Prior generated documents are preserved; newly generated applications use this design. Existing free source-grounded generation and owner-reviewed AI revisions remain separate.

Validation before deployment: 83 unit tests; Chromium desktop/tablet/phone navigation, separate chats, previews and revisions, mocked dictation and visual viewport, native file-input photo upload/preview and a multi-chunk 9 MiB upload. A full 1 GiB local upload completed with matching checksum and persisted size in 5.9 seconds; its temporary fixture was removed. No paid inference, client messages or submissions were used. Production checks separately reserve 1 GiB, exercise a 4 MiB chunk, idempotent retry and next chunk across the private HF proxy, then cancel the partial fixture. They do not transfer a full 1 GiB in production or verify the owner's device/provider configuration.
