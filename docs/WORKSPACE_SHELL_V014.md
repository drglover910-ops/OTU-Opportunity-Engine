# v0.14.0 — stable conversation workspace

Owner recordings showed that earlier cosmetic changes did not address the navigation/typing flow. The revised shell uses a fixed header, a persistent chat with its own scrolling message region and bottom composer, a collapsible 256px sidebar/64px icon rail, and one supporting pane. Tablet/phone navigation overlays the chat; desktop navigation can collapse without losing chat content. A dashboard-era margin:auto shrink-to-fit rule was removed so the shell reaches the viewport edges and panes cannot be clipped by unintended gutters.

Opportunities, Library, Connections, Explore, Help, files, conversation tools and other supporting views retain their original DOM/forms inside the independent pane. Opening one does not reload the chat or erase an unfinished message. Desktop panels share available width; at 1100px and below they overlay the right side, with inert background, focus containment, Escape and backdrop dismissal. Document review uses the same exclusive-pane behavior. On tablets, Ask the bot for changes closes the modal document pane before focusing the composer. Native dialogs such as photo previews retain topmost keyboard/Escape handling.

Workspace browsing has its own state and cannot mutate the active conversation's workspace/opportunity/chat ID. Selecting an actual conversation still deliberately changes chat scope through the existing validated APIs. Existing records, uploads, approval rules and AI usage limits are preserved.

Secondary controls now use anchored header/message/composer menus. Version and connection details remain in the header menu. The composer uses one initial line and bounded growth; duplicate conversation headings and persistent tool/action boxes no longer consume typing space. Message typography remains 16–17px with readable line spacing and a bounded central column. Matrix animation stays local, with reduced visual opacity and the existing motion controls.

Visible-viewport height and pan offsets are applied in one animation frame. The feed keeps its prior scroll position, or follows the bottom if already near it. No programmatic outer-page scrolling is used; New chat no longer forces the keyboard open. Pinch zoom is preserved. This is an implementation and simulation result, not a claim that the owner's actual Safari keyboard has been tested remotely.

Validation: 83 existing unit tests; node syntax checks; localhost-only Chromium fixture at scripts/check_workspace_ui.py for desktop, tablet and phone. The fixture covers chat separation, menus, rail, panel bounds, preserved draft/scope, file upload/photo preview, mocked dictation, simulated keyboard viewport/pan and reviewed document transitions. It blocks external browser requests and uses no paid inference or real microphone. Production health/assets are checked by the deployment workflow; actual owner-device Safari behavior remains the final manual check.
